# 提供ルール：大人1名1膳（お願いベースで確定）と提供順（前菜 → 膳 → デザート）

> 出典：オーナー／店舗からの運用ルール共有（2026-09-03）。
> 関連：[2026-06-04 議事録 §5](2026-06-04_議事録.md)（「大人1名1膳必須」の確定） / [2026-07-16 議事録 §2](2026-07-16_議事録_使用感デモ・UI方針.md)（食後デザートのホール側表示） / [要件定義（仮） 注意事項](../要件定義（仮）.md)

**一言サマリ**：注文ルールは **大人1名1膳を「確定でお願いします」とお客様に依頼**する運用。提供は必ず **前菜 → 注文された膳 → デザート** の順で流れる。**前菜とデザートは「注文」ではなく提供フローの一部**であり、注文データにも KDS のレーン分類にも存在しないのが現状。

---

## 1. 注文ルール：大人1名1膳（確定）

- **大人の方は 1 人 1 膳のご注文をお願いしている**（お客様への依頼としてお伝えし、確定扱い）。
- 子供とのシェアは可（[要件定義（仮）](../要件定義（仮）.md) の予約フォーム注意事項）。
- システム側の扱いは既定：**注文時に人数分のメニューが揃うまで確定不可**のバリデーション（[2026-06-04 議事録 §5](2026-06-04_議事録.md)）。人数の大人/子供内訳（`reservations.adults` / `kids`）と連動する（[db-design](../docs/db-design.md)）。

## 2. 提供順（確定）

```
前菜  →  注文された膳  →  デザート
```

- **前菜**：膳の前に必ず提供する。お客様の個別注文ではなく、**来店したら出るもの**。
- **膳**：お客様がタブレットで注文した品。大人1名につき1膳。
- **デザート**：膳をすべて出し終えた後に提供する（＝食後）。

## 3. システムへの影響（要検討・未実装）

| 論点 | 現状 | 論点の中身 |
| :--- | :--- | :--- |
| 前菜が注文データに無い | 品名として一切登場しない | 人数分の前菜を「誰がいつ出したか」を KDS で追えない。膳より先に出す必要があるのに、KDS のカードには現れない |
| デザートも注文データに無い | 同上 | [2026-07-16 議事録 §2](2026-07-16_議事録_使用感デモ・UI方針.md) の「キッチン側で全品用意完了（カード消去）→ フロント側にその卓の食後デザート表示」が、この提供順の**最後の1ステップ**にあたる。**未実装** |
| レーン分類に該当カテゴリが無い | `itemCategory()` は ご飯類 / サイド / ドリンク の3分類のみ（[kds-a-grid.html](../kds-a-grid.html) Issue #13） | 仮に前菜・デザートを品目として流すと、キーワードに当たらず**すべて「サイド」に落ちる**。提供順を画面で表現できない |
| 遷移先の資料割れ | [要件定義書](../docs/要件定義書.md) は「厨房完了 → **客側**デザート画面遷移」を将来拡張、[2026-07-16 議事録](2026-07-16_議事録_使用感デモ・UI方針.md) は「**ホール側**画面に表示」 | 7/16 の議事録が新しいがドキュメント未更新。**どちらが正か要確認** |

## 4. 次に確認したいこと

- 前菜は**人数分**を自動で出す想定か（＝大人人数と連動するのか、子供にも出るのか）。
- 前菜・デザートを **KDS 上で可視化する必要があるか**（出し忘れ防止のため表示するか、オペレーションで完結させるか）。
- デザート案内の表示先は **ホール側画面 / 客側タブレット** のどちらか（§3 の資料割れ）。
