# TableCheck の予約の書き出し：列の一覧と、要る列・要らない列（2026-10-21）

> **後日更新（2026-10-22）**：下記の「読めなかった」はPR #307時点の記録。PR #312で、タイトル行・「予約時間」・人数4区分・`数 × 品名`・xlsx・予約メモのアレルギー抽出に対応した。現行は `adults`・`seniors`・`children`・`kids` を合算せず保存し、合計は表示時に計算する。「苦手なもの」も注記へ取り込む。下表の「大人に足す／子どもに足す」は分析時の案であり、現行の保存方法ではない。元の分析・失敗結果は以下に保全し、現行手順は [中継サーバー README](../relay-server/README.md#予約の保存reservation-storejs) を参照する。取消・卓番の運用確認は未解決。

> 出典：持ち主から受け取った TableCheck の予約の書き出し（`デモデータ.xlsx`、2026-10-21）。「それがテーブルチェックのcsvだから」「必要なカラムとそうじゃないカラムがある」。
> 関連：[議事録 (2026-10-21)](2026-10-21_議事録_予約の取り込み.md)／[決定：予約のCSV取込と変更の反映](2026-10-21_決定_予約のCSV取込と変更の反映.md)／[運用：外国人のお客様は予約IDを見せる](2026-10-21_運用_外国人のお客様は予約IDを見せる.md)
> **個人情報について**：書き出しには名前・電話・メール・顧客IDなどが入っている。本書には列の名前と値の形だけを書き、値そのものは載せない。書き出しのファイルをリポジトリに入れない。

## ファイルの形

- 受け取ったのは **Excel（.xlsx）**。シートは1枚（「予約」）
- **1行目はタイトル（「予約」）だけ**で、**2行目が見出し**、3行目から予約が1行ずつ並ぶ
- 列は **72**。予約1件につき1行
- CSV で出したときも同じ並びか（タイトル行の有無・文字コード）は、まだ確かめていない

## 要る列（取り込む）

| 列 | 値の形 | こちらでの使い道 |
| :--- | :--- | :--- |
| 予約ID | 英大文字と数字の6文字 | 予約の ID（取り直しで同じ予約を上書きする鍵）。**外国人のお客様が見せる番号**と同じかを確かめる |
| 予約時間 | `YYYY-MM-DD HH:MM` | 来店日時。同じ値が「開始日」（`YYYY-MM-DD`）と「開始時刻」（`HH:MM`）にも分かれて入っている |
| 人数:大人 | 数 | 大人の人数 |
| 人数:シニア | 数 | 大人に足す |
| 人数:子供 | 数 | 子どもの人数（下の「確かめること」） |
| 人数:幼児 | 数 | 子どもに足す（下の「確かめること」） |
| 名前 | 文字（ひらがな・カタカナ・ローマ字） | 予約ストックに出す名前 |
| 注文 | `数 × 品名` を `, ` でつなぐ（例 `1 × 〇〇土鍋御膳, 2 × △△土鍋御膳`） | 事前メニュー。**数が品名の前**に来る |
| 食事制限・アレルギー | 文字 | アレルギー |
| 予約メモ | 文字。`質問1: アレルギーや…… 回答1: なし` のような予約フォームの質問と答え、`ご利用回数: 初来店` などが改行で並ぶ | **アレルギーの質問の答え**はアレルギーとして取り出す。残りはメモ |
| ステータス | 例 `確認` | 予約の状態（キャンセルなど、ほかの値はまだ見ていない） |
| テーブル | 例 `A1/2`、`B5` | TableCheck 側で割り当てた卓（下の「確かめること」） |

## あると良い列（取り込むか決める）

| 列 | 使い道の候補 |
| :--- | :--- |
| 苦手なもの | 厨房に出す（アレルギーではないが、膳を作るときに要る） |
| お好み | 同上 |
| 用途 | 例 `家族との食事`。記念日などの要望の手がかり（声かけテストの「記念日」） |
| 予約メモ 2・店舗メモ・顧客メモ | お店が書いたメモ。厨房・ホールに要るものがあるか |
| 滞在時間・終了時間 | 卓の回転の見積もり。今の KDS では使っていない |

## 要らない列（取り込まない）

- **個人情報で、厨房・ホールで使わないもの**：電話、Eメール、顧客ID、性別、会社名、肩書、氏・名（かな・漢字。「名前」があれば足りる）、顧客 2〜4 の名前、会員ID・会員プログラム・会員ステージ
- **記録・集計用**：作成者、作成日、更新者、更新日、来店経路、きっかけ、UTM（3列）、プロモーションコード、ポイント、タグ、フラグ
- **お金・POS**：注文合計金額、POS 伝票番号、POS 合計、支払ステータス、TableCheck Pay必要
- **店・席の設定**：店舗、店舗 ID、店舗 Web ID、フロアレイアウト、セクション、席のカテゴリ、テーブルの席のカテゴリ、禁煙・喫煙の希望、席タイプの希望、部屋番号、グループ名、営業担当
- **キャンセル理由タイプ・キャンセル理由**：取消かどうかは「ステータス」で分かる
- **終了日・終了時刻**：来店日時と取り違えないよう、来店日時の列として読まない

## 今の取込（試作）で読ませた結果

名前・電話・メール・顧客IDを作り物に置き換えて CSV にし、今の取込（PR #307 の版）に読ませた。**1件も取り込めなかった**。

1. 1行目のタイトル「予約」を見出しとして読み、どの列も分からない
2. タイトル行を除いても、「予約時間」を**時刻だけの列**として読み、日付の列が無いと判断して止まる（「開始日」「開始時刻」も読めない）
3. 「人数:シニア」を**合計人数**として読む。「人数:幼児」は読まない
4. 「注文」の `1 × 品名` を読めない（今は `品名 × 数` の形だけ）。品名が `1 × 〇〇` のまま、数が1で入る
5. .xlsx は読めない（CSV だけ）
6. 予約メモの中のアレルギーの答えを取り出さない

## 確かめること（店に）

- 書き出しは CSV と Excel のどちらで出すか。CSV のときもタイトル行があるか、文字コードは何か
- 「人数:子供」は何歳まで、「人数:幼児」は何歳までか。KDS は子どもを「幼N」（0〜2歳）と出しているので、TableCheck の「子供」をどう数えるか
- 「テーブル」は予約のときに TableCheck で決めた卓か。来店したときに変わることはあるか（今の業務フローでは卓は来店時に決める）。`A1/2` は卓をつないだ書き方か
- 「ステータス」に出る値の種類（確認のほか、キャンセル・来店・ノーショーなど）
- 予約フォームの質問は、アレルギーのほかに何があるか
