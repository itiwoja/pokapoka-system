# チビ伝はホール側で出す（運用実態による決定・2026-09-03）

> 出典：オーナー／店舗からの運用実態の共有（2026-09-03）。
> 更新対象：[2026-07-16 議事録 §5](2026-07-16_議事録_使用感デモ・UI方針.md)（「ホールモードは読取専用＝印刷を無効化」）

**一言サマリ**：チビ伝は **ホール側で出す**。配膳のお膳にテーブル番号と一緒にチビ伝を乗せて運ぶため、**伝票を持って動くのはホール**だから。現状の実装はキッチン専用（ホールでは印刷ボタンを非表示）で、**実態と逆**になっている。

---

## 1. なぜホール側なのか

- 配膳は**お膳（トレー）にテーブル番号を乗せて**運ぶ。
- そのお膳に**チビ伝を一緒に乗せる**。どの卓へ持っていくかがチビ伝で分かる。
- したがって**チビ伝を手にして動くのはホール**であり、出す操作もホール側にあるのが自然。

## 2. 現状の実装（実態と逆）

| | 実装 | 実態 |
| :--- | :--- | :--- |
| チビ伝の印刷 | **キッチン専用**。ホールモードでは印刷ボタンを非表示 | **ホールが出す** |

該当箇所は [kds-a-grid.html](../kds-a-grid.html) の `body.mode-hall .slip-btn { display: none; }`。

## 3. 元になっていた記述

[2026-07-16 議事録 §5](2026-07-16_議事録_使用感デモ・UI方針.md) に次の記述がある。

> 現状ホールモードは読取専用（品目・コンロ・並べ替え・印刷を無効化）であり、この「キッチンが操作しホールは見るだけ」という関係は維持される

この文の主題は §5「**注文商品の入れ替え（並び順の変更）はキッチンに主権**」であり、並び順の主権を確認する文脈で「現状こうなっている」と**現状説明として**印刷に触れたもの。**チビ伝を誰が出すかを検討して決めた記述ではない。**

なお [2026-06-04 オーナー確認事項](2026-06-04_オーナー確認事項_準備メモ.md) には「権限分け＝**厨房はタップのみ**／ホールは入力機能あり」とあり、こちらは今回の実態と整合する（ただし文脈は予約入力ボタンの話）。

## 4. 決定

- **チビ伝の印刷はホール側から行えるようにする。**
- 印刷は「ホールは読取専用」の例外とする。並び順・品目完了・コンロといった**調理そのものの操作の主権がキッチンにある点は変更しない**（§5 の決定は維持）。

## 5. 未決（実装前に確認する）

- **キッチンからも出せるままにするか、ホール専用にするか。**
  - 両方から出せる：デシャップで刷り直したい場面に対応できるが、二重印字の余地が残る
  - ホール専用：役割がはっきりする。ただしキッチン側で刷り直せなくなる
- **プリンターの物理的な設置場所**（キッチン寄りかホール寄りか）。ここが決まると上の判断も決まる。
