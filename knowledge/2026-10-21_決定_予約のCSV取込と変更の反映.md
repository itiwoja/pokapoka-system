> 関連：[打合せ準備 (2026-10-21)](2026-10-21_打合せ準備_KDS要望とTableCheck予約取込.md) 第2部／`relay-server/README.md`「予約の入口(試作・4方式)」／Issue #292／PR #307

> csvで取り込み変更があったとき変更

>

## 決めたこと

- **予約は TableCheck から CSV で取り込む**（打合せ準備 2-2 の「B. CSV」）。2026-10-11 に API 連携をやめた後の、予約の主な入口になる
- **予約に変更があったときは、TableCheck から CSV を出し直して、もう一度取り込む**。変わった予約を予約入力画面で手で直すのではない
- **当日に、その日の予約を全部チェックする**（CSV で取り込む）。**当日の予約は無い**ので、当日に取り込めば、前日までの新規・キャンセル・人数や時間の変更がすべて入る

### 6/3 の記録との食い違い（確かめる）

[2026-06-03 運用確認](2026-06-03_運用確認_電源充電・KDS台数.md) C には「**当日予約が多々ある**（当日電話予約／来店後に予約して戻る）」「当日は特にメニュー予約を推奨」とあり、今回の「当日の予約はない」と食い違う。次のどれかを確かめる。

- 6/3 の後に運用が変わり、当日予約は受けなくなった
- その他

電話の当日予約が今もあるなら、それをどこから入れるか（#292）は残る。

## 変更に気づけるか

店に届く通知で分かること・分からないこと（持ち主から。3つ目の原文。「人数は時間の変更」は「人数や時間の変更」と読んだ）：

| 予約の動き | 通知 |
| :--- | :--- |
| 新規予約 | 来る |
| キャンセル | 来る |
| 人数・時間の変更 | **来ない（分からない）** |

ここから出てくること：

- 人数・時間の変更は、通知を見て「変わったから取り込み直す」ことができない。そこで**当日にその日の予約を全部取り込む**（上の決定）。当日の予約は無いので、当日の取り込みで前日までの変更はすべて入る
- 当日に1回だけ取り込むなら、前回の取り込みとの違いを気にする場面は少ない。当日のうちに取り込み直す（電話で変更を受けた、など）ときは、**前回から人数・時刻が変わった予約を、取り込む前の確認画面で目立たせる**と、店が変更に気づける（今の確認画面は、取り込む内容を並べるだけ）
- 新規予約・キャンセルの通知は、予約の入口としては使わない（当日の CSV に全部載るため）

当日の電話予約など CSV では間に合わない予約の扱い（手入力との併用。打合せ準備 2-4）は、この決定には含まれていない。

## 今の試作で、変更を取り込むとどうなるか

予約入力画面の「CSV取込」（`relay-server/reservation-import.js` → `reservation-store.js`）は、**予約番号ごとに上書き**する（upsert）。

| 変更の種類 | CSV の取り直しでの結果 | 手入力の「変更」での結果 |
| :--- | :--- | :--- |
| 日時・人数・メニュー・要望が変わった | 予約番号の列があれば反映される。無いと、日時と名前から作る番号が変わり**二重**になる | 反映される |
| TableCheck で取り消した | 取消の行（ステータス）が出力に出れば反映される。**出力から消えるだけだと、こちらでは消えない**（差分で消す処理が無い） | 「取消」で反映される |
| こちらで手で直した卓番・メモ・取消 | **CSV の値で上書きされる**。手で取り消した予約も、CSV がまだ「確定」なら生き返る | — |
| 同じ予約を手入力と CSV の両方で入れた | 予約番号が違うので**二重**になる（炊飯準備の合図も2つ出る） | — |

## 決定を実装に移すときにやること

変更は CSV の取り直しで反映するので、**取り直しても壊れない**ことが要る。上の表の太字の所を直す。

1. ~~実物の CSV を1つもらう~~ → **もらった**（2026-10-21、Excel・72列）。列の一覧と要る・要らないの仕分け、今の取込で読めなかった所は [TableCheck の予約の書き出しの列](2026-10-21_TableCheck予約CSVの列.md)。予約番号は「予約ID」列にある。取消が「ステータス」にどう出るか、取消した予約が書き出しから消えるかは、まだ見ていない
2. **予約番号の列を必須にする**。無い CSV は取り込む前の確認画面で止める（取り直すたびに二重になるのを防ぐ）。外国人のお客様は来店時に予約IDを見せるので、予約番号は来店時に予約を探す手がかりにもなる（[運用：外国人のお客様は予約IDを見せる](2026-10-21_運用_外国人のお客様は予約IDを見せる.md)）
3. **CSV から消えた予約の扱いを決める**。出力した日付の範囲に入っているのに CSV に無い予約を、取消として扱うか（TableCheck で取り消した予約が出力から消える場合に要る）
4. **こちらで入れた値を取り直しで消さない**。卓番（来店時に入れる）・こちらで足したメモは、CSV に列が無ければ上書きしない。こちらで取り消した予約を、CSV の取り直しで生き返らせるかを決める
5. **手入力の予約と CSV の予約を突き合わせる**。当日の電話予約を手入力し、後で TableCheck にも入れて CSV に載ると二重になる。手入力に予約番号の欄を足すか、当日分は CSV で取り込まない線を引く（当日予約の扱いは別に決める。打合せ準備 2-4）
6. **当日の取り込みの手順を決める**：誰が・何時に（炊飯準備の合図が出る「来店30分前」より前、つまり最初の予約の30分以上前）・どの端末で、その日の分の CSV を出して取り込むか（打合せ準備 2-3 の 5・7）。TableCheck で「当日分だけ」を出せるかも確かめる
7. 当日のうちに取り込み直すことがあるなら、**取り込む前の確認画面に、前回から変わった予約（人数・時刻・メニュー）を出す**

## 確かめること（店に）

- 「当日の予約はない」は、電話の当日予約も含めて無いという意味か（上の「6/3 の記録との食い違い」）
- 当日、何時ごろに予約をチェックしているか。最初の予約は何時ごろか
- 人数・時間の変更は、今はどうやって気づいているか（当日のチェックで気づく、お客様からの電話、など）

## 済んでいること

- CSV に「作成日時」「更新日時」などの列があっても、来店日時と取り違えないようにした（PR #307）
