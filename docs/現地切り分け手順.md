# 現地切り分け手順（Issue #202）

## 0. 安全な確認

設定変更やファイアウォール開放は行わず、まず `node relay-server/preflight.js` を実行して出力を保存する。APIキーや共有トークンはログ・写真・Issueへ貼らない。

## 1. 中継サーバーとLAN

1. ミニPCで `config/config.json` の `server.host` が固定された店内LAN IP、`server.port` が `8000` であることを確認する。
2. `node relay-server/server.js` を起動し、ミニPC上で `http://127.0.0.1:8000/api/health` を開く。
3. 別端末から `http://<固定IP>:8000/api/health` と `/` を開く。
4. `preflight.js` の待受、IP固定、ネットワークプロファイル、ファイアウォール結果を確認する。

| 症状 | 確認 | 次の対応 |
|---|---|---|
| ミニPCでも不可 | プロセス・ポート・ログ | サーバー起動と設定を修正 |
| ミニPCのみ可 | bind先・固定IP・受信規則 | 店内LAN IPへbindし、スタッフLANだけ許可 |
| スタッフ端末のみ不可 | SSID・VLAN・端末IP | 同一スタッフネットワークへ接続 |
| ゲスト端末から可 | SSID/VLAN分離・ACL | ゲストから8000/TCPを遮断し、再確認 |

## 2. QR・KDS・注文

`/qr` のURLが固定IPを指すことを確認する。QRで開けない場合はQRを使わず同じURLを手入力し、URL問題かネットワーク問題かを分離する。`/demo` で予約の作成・更新・取消、注文端末から `POST /api/orders` の新規・同一ID再送・取消を確認する。

## 3. プリンター

電源・用紙・LAN/WLANリンク、固定IP、RAW TCP `9100` の順に確認する。`preflight.js` のプリンター診断結果を保存し、印刷失敗時はアプリログとプリンター状態を紐付ける。`POST /api/print` が成功しない場合、ブラウザ印刷が正常に出るなら「アプリ経路不合格・運用継続可（ブラウザ印刷）」と判定する。ブラウザ印刷も不可ならプリンター／用紙／端末を切り分ける。

## 4. エスカレーション

15分で原因が特定できない場合は、時刻、端末IP、SSID区分、コマンド出力、サーバーログ、画面／紙の写真、再現手順を #203 の記録様式へ転記し、新規Issueへリンクする。
