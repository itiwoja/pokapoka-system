# デシャップ画面 仕様（会議決定の統合・実装用）

> 出典：docs/PRD.md ＋ knowledge/（2026-05-29 KDS画面詳細要件 / 2026-06-03 色分け・座席DB / 2026-06-04 議事録 / 2026-06-18 議事録）の確定事項を統合。
> 目的：厨房の「デシャップ（dish-up）画面」の実装用仕様。POS連携は対象外だが、現在は注文サーバー → relay → KDS の通信経路を実装済み。中止したのは TableCheck API 連携であり、予約ファイル取込は利用する。
> **2026-10-22 整合性確認**：以下の現行説明と、後段の2026-07-14時点の受け入れ記録を区別する。最新方針は [現在地](../knowledge/現状.md)。Next.js 移行は決定したが範囲・時期は未確定で、本書は移行前の HTML / Node.js 実装を説明する。

## 現行の技術構成と制約
- HTML/CSS/Vanilla JS を使用し、フレームワーク・外部CDNは使わない。ただし `slip-renderer.js`・`relay-server/party-size.js`・同梱通知音を参照し、relay 配信時は `kds-bridge.js` を注入する。**単一HTMLだけで全機能が完結する構成ではない**。通信断では既存表示・手元の操作状態を保持するが、新着取得・別端末同期・サーバー印刷は接続が必要。
- **産業用計器UI（完全機能特化）**：商用デシャップ Okage DDS を参考に「黒ヘッダー `#1A1A1A` ＋明るい盤面 `#E9ECEF`」でクロームと作業面を分離。白カード `#FFFFFF` に清潔な実影＋角丸で"意図された計器"に。文字主 `#14161A` / 副 `#565B61`。厨房の距離から一瞬で状態を読ませることを最優先し、色は「意味」にのみ使う（緊急度=カード上帯の高彩度塗り 緑→黄→赤 / 種別=アンダーライン・チップ 新規=藍/予約=金、赤は経過警告10分+専用）。主要CTAはオレンジ `#C25200`（赤と分離）。数量は黒塗り四角＋白数字、コンロはサブ行の「コンロ割当」で1〜10展開、カード下部の帯は使用中の番号があるときだけ出す。過度な装飾は用いない。全要素AA（本文4.5:1/非テキスト3:1）・タップ域（品目64px+/補助44px+）準拠。
- **データ契約**：`window.KDS_ORDERS=[{id,table,type:"new"|"reserved",start,people,items:[{name,qty,options,allergies,done}]}]` を1秒ポーリング。
- **同期**：LocalStorage / BroadcastChannel は同一originのブラウザ内のタブ間のみ。relay 配信時は `/api/kitchen-state` 経由でコンロ・完了数・タイマーロック・並び順・削除済みIDを別端末にも共有する。予約は各端末が `/api/stock` を取得する。炊飯cue・卓番上書き・提供準備完了cue・前菜／デザート提供確認・予約から着手したカードは別端末同期の対象外。
- **保存**：予約は relay の SQLite。relay の注文はメモリで扱い、当日分の控えを SQLite に残して再起動後に読み戻す。厨房状態・座席占有はメモリ。KDS の表示状態は LocalStorage。詳細は [データ設計 §1](db-design.md#1-現行構成予約保存と中継注文の一時保持)。
- AA(本文4.5:1/非テキスト3:1)・卓番号28px+・品名22px+・1MB以下。
- **タップ領域**：主要操作（品目タップ）は**64px+**。補助ボタン（コンロ番号・伝票プレビュー・権限切替等）は**WCAG AA相当の44px+**を下限とする。コンロは5列×2行の画面幅制約があるため一律64pxは課さない。
- **日本語オンリー**（オーナー決定）。多言語対応・言語トグルは本リポジトリ（厨房KDS）のスコープ外。

## 画面レイアウト（2ペイン）
- **左＝メイン配膳エリア**：進行中オーダーのカードグリッド。**縦スクロールの折返しグリッド・時系列順（新着は末尾＝行優先で追加＝配膳/FIFO順）**。先頭挿入はしない＝作業中カードの位置を動かさない。新規オーダーは、Android Chromeで「通知音ON」を押した後に同梱した実録のししおどしの竹の打音を1回鳴らす。初回スナップショット、同一`orderId`の再送、変化のないポーリングでは鳴らさない（10分超の遅延アラート音は対象外）。
- **右＝予約ストックパネル**：当日予約を時間順に縦並び（縦スクロール）。
- **権限モード切替**（ヘッダ）：**キッチン**＝品目完了・コンロ・並べ替え／**ホール**＝厨房状態は読取専用、予約入力・移動、前菜／デザート提供確認・印刷は操作可能。

## 注文端末→デシャップ送信項目

- 注文端末側の入力順：**卓番（最初に入力）** → **予約 or 新規** → **メニュー選択（スライド式でメニュー画像をタップ）** → **数量（＋／－ボタンで増減）** → **オプション（アレルギー表示あり、オプションあり／なし選択）**。
- デシャップ行き必須項目：**卓番**、**注文したメニュー名**、**数量**、**オプション内容（アレルギー情報含む）**。
- KDS の表示契約は `type:"reserved"|"new"`。relay の通常注文受付APIには `type` 項目はなく新規として配信する。予約はストックから着手した `res-*` カードが予約種別になる。
- アレルギー情報は `allergies` 推奨。注文端末側の都合で `options` に含める場合も、品目直下に常時表示する。

## オーダーカード（メイン）
- **色（最新決定）**：新規=**水色系(淡)** / 予約=**黄色系(淡)** / **赤は経過警告(10分+)専用**（カード背景に赤を使わない）。予約黄色と経過琥珀が混同しないよう低彩度カード＋高彩度バッジ＋数値併記。
- 表示：卓番号(大)・人数(可能なら大人/子供内訳)・受付HH:MM・**経過時間(分・3段階 0-4緑/5-9琥珀/10+赤)**・品名(略称対応/長文は省略)・数量・**オプション/アレルギー/備考は常時表示**（品目直下・副色）。
- **品目タップ**＝数量2以上は1個ずつ数え上げ（`0/3→1/3→2/3→完了`、黒塗り box は「完了個数 /全数」を併記。完了したら打ち消し線＋全数表示に切替）。完了行タップで1個分未完了へ戻る。**長押し(0.8s)で誤タップを1個分戻す**（#153）。全品目完了後は厨房で非表示、ホールではデザート提供までカードを保持し、提供確認後に消去する。
- **コンロ番号 1〜10**（2行）：タップ循環 **未使用→黒(コンロ使用中)→赤(タイマー管理中)→未使用**。コンロ枠とタイマー枠は同番号でも別資源。他卓が占有した種別は読み飛ばし、両方が占有されている番号は押下不可（横取りしない）。relay 配信時は厨房状態として別端末にも同期する。
  - 厨房で卓を全品完了にしたら、「戻す」の猶予（6秒）が過ぎた時点でその卓のコンロ・タイマーをすべて外す（他タブ・中継サーバーにも未使用として伝える）。カードはホールでデザートを出すまで残るため、外さないと別の卓の番号を塞いでいた。タップで埋まっている種別を読み飛ばした結果、自分の割り当てが外れるときは「タイマー4は卓3が使用中のため、コンロ4を外しました」と知らせる（#298）。蒸らし（#161）は未決のまま。
- **前菜の「出した」は6秒だけ取り消せる（ホール）**：ホールでは提供済みの前菜の帯を畳む（#230）ため、押した直後にデザートと同じ形の「卓 N の前菜を出しました［戻す］」を6秒出し、押されたら前菜を未提供に戻す（#295）。厨房へ切り替えると閉じる。
- **長押し(0.8〜2秒)＋アニメで移動**（並べ替え＝配膳順変更）。誤操作防止に長押し必須＋取消/戻る。
- **チビ伝印刷**：ホールで**注文単位で全品目を1枚にまとめた伝票**を出す。`slip-renderer.js` によるプレビューと画像を `/api/print` へ送る。プリンター未設定・送信失敗時は `window.print()` へフォールバックする。キッチンでは印刷ボタンを非表示。
  - 新着注文で伝票プレビューを自動的に開く「自動プレビュー トグル」（旧称「自動印刷」）は不要と判断し**廃止**。プレビューはカードの印刷ボタンからの手動表示のみ。
- **スコープ外の先行実装（既定OFF）**：**タイマーロック（停/再）**・**注文削除（×）** は会議未決定のためフィーチャーフラグで無効化し、UIに表示しない（`FEATURE_TIMER_LOCK` / `FEATURE_DELETE_ORDER`）。正式決定が出た段階で本仕様に追記のうえ有効化する。

### カードの密度と品目行の操作感（2026-10-16）

1280×800 のタブレットで進行中カードが3列×1.5行しか収まらず、10分超過のカードが初期表示の外に出ていたため、品目行64px・品名22px+・卓番28px+ は保ったまま、カードの品目以外を詰めた（3品目カードで約450px→約355px、1920×1200 では15枚が無スクロールで収まる）。

- バナーの卓番は 44px、サブ行は 44px ボタンの高さ（46px）に合わせる。
- 「コンロ割当」ボタンはサブ行（卓番の隣）に置く。カード下部のコンロ帯は、使用中の番号があるか展開中のときだけ表示する（`:has()` で判定。非対応ブラウザでは従来どおり常時表示）。
- 「コンロ割当」⇔「閉じる」で文言が変わっても、ボタンの幅は長いほうの文言の幅のまま変えない。隣の「卓番」が横へずれて、閉じようとして卓番のテンキーを開くのを防ぐ（#295）。
- キッチンの前菜「未提供」帯（読取専用）は1行の細い帯にする。ホールの操作ボタン付き帯は変えない。
- 品目行は行全体に白い面を敷いてタップ対象と分かるようにし、タップ時に行を一度明滅させる。数量箱は 40px・数字 22px、`完了/全数` の全数も 15px に拡大する。長押し（1個戻す）は押下0.2秒後から行の下辺に進捗帯が伸び、0.8秒で成立する。
- HUD のコンロ／タイマー列は使用中の番号だけを並べ、無いときは「コンロ なし／タイマー なし」と表示する。

## 予約ストックパネル（右）
- 各カード：予約時間（最大表示）・人数（大人・シニア・子供・幼児の4区分）・名前・メニュー（名称/略称・常時表示）。**時間順に自動ソート**・縦スクロール。区分・合計・内訳表示は `party-size.js` で共通化。
- **追加ボタン(＋)**→フォーム（時間・人数・名前・メニュー[チェック＋個数]）。営業前一括入力＋営業中追加。
- **30分前通知**：予約時間30分前に該当カード右上にバッジ/点滅で通知（自動移動しない）。
- **来店→メインへ**：席番(卓番)を入力して「着手/配膳へ」ボタンでメイン配膳エリアへ移動（予約→進行中）。
- 席だけ予約(メニュー未確定)はストックに載せない（新規扱い）。
- **予約の削除（×）は2段階**：注文削除（#68）と同じく、1回目で「削除?」に変わり、3秒（`DELETE_ARM_MS`）以内にもう一度押したときだけ消す。「調理開始」の隣にあるため、1回の押し間違いで消さない（#295）。

## モード/権限
- キッチン：品目完了・コンロ・並べ替え、炊飯cue確認、厨房限定卓番上書き。前菜の提供状態は閲覧のみ、デザート帯・印刷ボタンは非表示。
- ホール：厨房状態は閲覧のみ。予約ストックの追加／席番入力・着手、前菜／デザート提供確認、チビ伝印刷が可能。

## TableCheck API中止と予約ファイル取込

2026-10-11 に TableCheck API連携を中止し、2026-10-21 に CSV 取込を主な入口（朝1回・変更時再取込）に決定した。現在は `/reservations` に手入力・CSV／Excel取込・貼り付け・メールの入口と一覧・変更・取消を試作済み。正式な管理画面や再取込時の取消・手修正値の保護は未決／未対応。

旧APIの暫定データ契約・取得・同期・モック・デモコンソールは [`archive/tablecheck/`](../archive/tablecheck/README.md) に保全する。現行のファイル取込・予約保存・配信の仕様は [中継サーバー README](../relay-server/README.md) を参照する。

## デモとサーバー配信
- KDS単体の起動時／空時はデモを投入できる。relay 配信時は `__KDS_SUPPRESS_DEMO__`、または `?nodemo=1` で自動デモを抑止し、登録済みの予約・注文を取得する（未登録なら空）。
- コンソールから `window.KDS_ORDERS` 書込でも反映。

## Issue #155・#159・#160・#152 phase1（同一ブラウザ）

- ホールモードの既定表示は、従来のグリッド＋予約ストックを表示した読取専用とする。比較prototype A/B/C（Aは従来の進行中＋予約の2ペイン、Bは予約ストック主表示＋進行中compact、Cは提供準備完了主表示＋予約ストック副表示＋進行中summary）はコードを保持するが、2026-09-03の判断により `HALL_PROTO_ENABLED = false` で既定無効とする。フラグを有効化した場合のみ、選択をホールに表示し、`#hall=A|B|C` と `kds_hall_proto_v1` へ保存する。有効hash、有効LocalStorage、Aの順で初期値を決め、無効hashはAへ正規化する。キッチンのgrid/laneはprototype選択の影響を受けない。
- 予約メニューを既存の `itemCategory` で判定し、rice品目を1品以上含み予約時刻まで30分以内（時刻超過を含む）の全予約へ独立した「炊飯準備」cueを表示する。非rice・31分以上には表示せず、同時表示件数に上限を設けない。cue状態はrid単位で `kds_rice_cue_v1` に保存し、確認操作はキッチンだけに許可する。
- 厨房限定卓番overrideは `kds_table_override_v1` にorder id単位で保存する。`effectiveTable(order)` を表示・伝票preview・hall-ready snapshot・コンロ所有卓表示にだけ適用し、`window.KDS_ORDERS`、`order.table`、relay/POS/TableCheck、`/api/seats` は変更しない。重複候補は初回決定で保存せず警告し、同一候補の「重複を許可して変更」を2回目の決定として保存する。候補変更、モーダル閉鎖、モード変更で確認状態を解除する。卓番ダイヤルは今の実効卓番を表示して開き、最初の番号タップでその値を置き換える（卓11で「1」「2」→12。追記して111にしない #295）。⌫・全消・ゾーンを先に押した場合は、以降の番号を追記する。予約の「調理開始」の卓番ダイヤルは下書きの続きに追記する（従来どおり）。
- 全品目完了時はカード消去前に `kds_hall_ready_v1` へorder id単位のsnapshot（effective卓番、完了時刻、品目要約）をidempotentに作る。cueはホール専用で、dismissed tombstoneは当日中保持する。dismissは専用6秒undoでactiveへ戻せ、既存厨房完了undoとはstate/timerを共有しない。
- 炊飯準備cue（`kds_rice_cue_v1`）は `kds_sync` の同一originタブ間だけで同期し、relayへ送らない。提供準備完了（`kds_hall_ready_v1`）と前菜/デザート（`kds_serve_cue_v1`）は、厨房とホールを別端末にするとデザート待ちのカードが消えるため、#288 で `KITCHEN_EVENTS` に加え、`/api/kitchen-state` 経由で別端末とも同期する。卓番override（`kds_table_override_v1`）も、チビ伝はホールで刷る（#226）ため別端末では元の卓番で出ていたので、#293 で同じ経路に加える。運ぶのは表示上の上書きだけで、`order.table`・relayの注文・`/api/seats` は変えない。#155最終選定、#152完全版、上流書戻しは別計画とする。

## Issue #204 現行版への確認済み記録の適用範囲

## React 版（/kds-next）

- **目的**: 要素を減らし、厨房スタッフが使う操作だけに絞った画面。キッチン専用（権限切替なし）。現行 `/kds` と並行して作り、受け入れ後に切り替える。
- **残す機能（4つ）**
  - 注文カード＋品目タップで完了
  - 予約ストック（当日の予約を時間順に表示）
  - コンロ番号（1〜10）
  - 伝票印刷
- **出さないもの**
  - キッチン/ホール切替、グリッド/レーン切替、ホール表示案A/B/C
  - プリンター IP 設定、同期状態パネル、デモ投入ボタン、HUD のコンロ一覧
  - 並べ替えドラッグ、タイマーロック、注文削除、米 cue/提供 cue、卓番上書き
  - 予約の追加フォーム（予約の入力は `/reservations` など別画面に任せる）
  - 通知音 ON ボタン
  - ホール操作全般も、この画面には入れない
- **技術**
  - React + Vite で作り、ビルドで外部参照のない1ファイル `kds-next.html`（リポジトリ直下）にする。完全オフラインの制約は現行と同じく守る。
  - データは現行と同じ localStorage / BroadcastChannel の契約を使い、`kds-bridge.js` で中継サーバーと同期する。現行画面と同時に開いても状態は揃う。
  - ソースは `kds-app/`。詳細は [`kds-app/README.md`](../kds-app/README.md)。
- **参考にした設計の慣行（2026-10-23 調査）**
  - 品目の合計（商用 KDS の All Day View）：進行中の全カードから品名ごとの残り個数を上部に1行で出す。同じ品を何件分かまとめて仕込むときに、カードを数えて回らなくてよい。
  - 補足（オプション）は品名に埋もれないよう本文色で出し、「抜き」「なし」などの打ち消しは太字、アレルギーは赤太字にする。アレルギーと打ち消しを最も目立たせ、省略しない。
  - 新着カードは表示直後に一度だけ明滅させる（初回表示では光らせない）。通知音と合わせて、目の端でも気づける。
  - 10分超は上辺の帯の色だけに頼らず、経過時間の数字を太く濃くして色覚に依らず分かるようにする。
  - 手が濡れた・手袋のままでも押せるよう、ボタンは 48px 以上にする（品目行は 64px）。
  - 採らなかったもの：暗い盤面（反射対策として勧める業者もあるが、本仕様は明るい盤面と決めている）、カード見出しタップで注文ごと完了（品目タップで十分で、誤操作の余地を増やさない）、ページ送り（縦スクロールで足りる）。
- **配信**
  - 中継サーバーが `/kds-next` で `kds-next.html` を配信する（`relay-server/routes/static.js`）。
  - ブリッジ script は `kds-next.html` 自身が読むため、中継サーバーは差し込まない（二重読み込み防止）。
  - 現行 `/kds`（`kds-a-grid.html`）はそのまま残す。
