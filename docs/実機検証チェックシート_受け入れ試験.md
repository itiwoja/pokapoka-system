## 使い方

このシートは、実機検証当日に確認結果を同じ形式で記録するためのものです。各項目について、確認操作を行ったあとに「実測結果」「合否」「証跡」「不具合Issue」を記入してください。

このシート自体は試験結果を保証しません。実機、店内LAN、注文端末、実プリンター、TableCheck LIVEを実際に確認していない項目を、推測で合格にしないでください。

### 記録時の安全ルール

- IPアドレス、SSID、共有トークン、APIキー、Cookie、Authorizationヘッダー、TableCheckの資格情報は、このシート・証跡ファイル名・Issueコメントに記録しない。
- TableCheckの実データや個人情報を証跡に含めない。必要な場合は、匿名化したテストID・件数・状態だけを残す。
- 証跡欄には、画面名・端末識別名・日時・結果の要約・安全なファイル名を記録する。元ログを添付する場合も、秘密情報を除去してから保存する。
- 端末識別名は、KDS-A、KDS-B、注文端末-Aのような一般名を使う。

## 判定ルール

合否欄には、次のいずれかを記入します。

| 判定 | 使い方 |
| --- | --- |
| 合格 | 期待結果を満たし、実測結果と証跡が記録され、不具合がない場合は「不具合Issue: なし」と明記した場合だけ使用する。 |
| 不合格 | 期待結果を満たさない場合。原因と不具合Issueを記録する。 |
| 保留 | 機材・権限・環境待ちなどで判定できない場合。再確認条件と担当を記録する。 |
| N/A | Issue #201の条件付き項目を実施対象外とする場合だけ使用する。対象外の理由を必ず記録し、合格とは数えない。 |

実測結果、証跡、合否のいずれかが空欄の項目は未完了です。未実施・未確認を合格に変更しないでください。
