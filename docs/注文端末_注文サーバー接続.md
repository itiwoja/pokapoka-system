# 注文端末と注文サーバーの接続先

2026-09-11に、注文端末→サブモジュール内の既存注文サーバーの仕様を確定した。

| 経路 | 送信先 | 商品の指定 | 今回の扱い |
|---|---|---|---|
| 注文画面 → `order-terminal/order-system` | 既定3001番 `/api/orders` | `menuId` と `selectedOptionIds` | 実装対象。人数、卓番、個数、同一要求の再送を扱う |
| `order-client.js` → `relay-server` | 既定8000番 `/api/orders` | `name` | 従来の中継サーバー用通信。上のAPIとは別の契約 |
| `relay-server/database.js` | HTTP APIなし | モックの `productId` | 独立したSQLiteモック。実注文の保存先ではない |

パスが同じ `/api/orders` でも、ポートとデータ形式が異なる。注文画面の `VITE_API_BASE_URL` は商品マスターを持つ注文サーバーへ向ける。注文端末から中継サーバー・KDSまでを接続した状態ではない。

## 送信データ

```json
{
  "requestId": "端末が発行して再送時も維持するID",
  "tableNos": [3],
  "people": 2,
  "items": [
    { "menuId": "商品マスターのid", "quantity": 2, "selectedOptionIds": [] }
  ]
}
```

商品名や価格は送らない。商品を指す `menuId` は `GET /api/menus` の `id` を使用し、商品コード `code` やモックの商品IDを流用しない。利用人数は注文全体の人数であり、個数の合計とは別に入力する。

フィールドの型・上限、受付応答、再送・入力修正・DB更新の契約は、サブモジュールの [ORDER_API.md](https://github.com/mukkunaru/restaurant-order-system/blob/0ed4d664ca75af5ecfd3c9ebea26073ea8d9b7fd/ORDER_API.md) を正本とする。ローカルでは `order-terminal/ORDER_API.md` を参照する。

## コードの取得と検証

```powershell
git submodule update --init order-terminal
```

コードは `order-terminal/オーダー端末アプリ作成`、注文サーバーは `order-terminal/order-system` にある。導入手順はサブモジュールの `OPERATIONS.md` と `ORDER_API.md` を参照する。人数のDB項目追加があるため、サーバーと画面を併せて更新する。

親リポジトリではサブモジュールのコミットを固定する。注文端末の変更はサブモジュール側でレビューし、そのコミットをこのリポジトリから参照する。
