# 注文画面への通信モジュール組み込み

画面チームはデザイン・カートを担当し、このリポジトリの `order-client.js` が送信・受付確認・端末保存・再送を担当する。ブラウザ用の依存ライブラリなしのモジュール。

## 組み込み例

`order-client.js` を注文画面のプロジェクトへコピーし、画面と `/api/orders` を同じオリジン（スキーム・ホスト・ポート）で配信する。別オリジンからのCORS接続は今回の対象外。現行relayの静的配信は許可リスト制なので、画面ファイルを置くだけでは公開されない。画面統合時に配信設定を追加する。

```html
<script src="./order-client.js"></script>
<script>
const orders = OrderClient.create({
  onChange(order) {
    // pending: 未送信／再送待ち、sending: 送信中、sent: 受付済み
    // failed: 入力／認証の確認が必要、needs_review: スタッフ確認が必要
    renderOrderStatus(order.orderId, order.status, order.error);
  },
  onError(error) { showStorageError(error.message); }
});
async function initialize() {
  (await orders.list()).forEach(order => renderOrderStatus(order.orderId, order.status, order.error));
  orders.start();
}
async function confirmOrder(cart) {
  // ボタンを処理中は無効化し、同じカートを2回submitしない。
  // 戻り値は「端末への保存完了」であり、サーバー受付完了ではない。
  const orderId = await orders.submit({
    table: cart.table,
    people: cart.people,
    items: cart.items.map(item => ({ name: item.name, qty: item.qty,
      note: item.note, allergies: item.allergies }))
  });
  return orderId;
}
initialize().catch(error => showStorageError(error.message));
</script>
```

上の `renderOrderStatus`・`showStorageError`・ボタン制御は画面チームが実装する。`submit` の失敗も画面側で捕捉し、カートを保持する。`submit` 成功後は同じカートの再確定を防ぎ、受付完了は `sent` で表示する。

## 通信の契約

- IndexedDBの保存トランザクション完了後に送信。保存不可の場合は送信しない。
- 自動生成した注文ID・送信内容・注文時刻を保存し、再読込後も同じ内容を再送する。既存IDへの `submit` は拒否する。
- HTTP 200/201・`ok: true`・一致する注文IDが揃って初めて `sent`。重複受付も成功。
- 通信失敗・タイムアウト・408・429・5xx等は1秒から最大30秒間隔で再送。その他4xxは `failed` として停止する。
- 認証設定を直した後の再送は `await orders.retry(orderId)`。不正な注文内容の変更や取消はこのモジュールの対象外。
- 作成から30分を超えた未確認注文は自動投入せず `needs_review`。スタッフがデシャップ等で受付状況を照合する。店舗判断で `maxAgeMs` を設定できる。
- Cookie認証を利用する。必要なら `getToken: () => token` でBearer認証を指定できる。トークンをキューに保存しない。

## 統合・実機確認で残る項目

注文画面への組み込み、HTTPS終端、端末のIndexedDB保存と再読込、Wi-Fi切断／復帰、二重タップ防止、認証、デシャップ表示を実機で確認する。自動テストはメモリの保存アダプターと実HTTPサーバーを使用し、ブラウザのIndexedDB自体は未検証。

1端末につき注文画面は1タブ・1クライアントで運用する。複数タブの排他制御は未実装。同じIDの再送はサーバーで重複排除されるが、同じカートから別IDを生成する操作は画面側で防ぐ必要がある。

`sent` はサーバーのメモリへの受付を示す。サーバー再起動で注文が消えた場合の復元は対象外。端末の送信済み記録は確認用に残し、自動再送しない。端末記録の保管期間・削除UIは運用確定後に追加する。ブラウザを閉じている間のバックグラウンド送信も行わない。
